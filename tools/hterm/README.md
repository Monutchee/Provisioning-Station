# Terminal asset maintenance

Ordinary Go builds use checked-in embedded assets and require no Node.js.
Maintainers regenerating those assets need Linux, Git, tar, Node.js 24 and npm 11:

```sh
git submodule update --init third_party/libapps
cd tools/hterm
npm ci --ignore-scripts
npm run build
npm run check
```

`build.mjs` asserts the exact official source revision, exports a tracked snapshot
to a temporary directory and bundles the upstream resource shims, punycode and
hterm/libdot entry points with locked Rollup dependencies. Git metadata comes
from the pinned commit, never the host time or checkout branch. It also extracts
English messages, licenses and a bundle checksum. It leaves the submodule
untouched. `check` regenerates independently and compares all generated bytes.
Source and generated output are upgraded together; commit both the submodule
pointer and assets. Rollback means reverting that commit; the UART API and stored
transcripts have no schema changes.

For browser regression tests, build the real server and install Playwright's
Chromium (build/test tools only):

```sh
go build -o /tmp/mnc-station-browser ../../cmd/mnc-station
npx playwright install chromium
STATION_BINARY=/tmp/mnc-station-browser npm test
```

`CHROMIUM_EXECUTABLE` can select an already installed Chromium. Tests launch the
compiled server on loopback with a temporary data directory, exercise its actual
CSP/embedded assets, and mock API/WebSocket data; no serial hardware is opened.
The browser suite covers input/observer guards, streaming Unicode, ANSI, rolling
history, transcript reset, resize, selection, and remote browser-action rejection.

The adapter intentionally uses a few private hterm row/cache methods for rolling
history because upstream has no bounded rolling-history preference. Review those
methods and run the real browser suite whenever changing the source pin.
